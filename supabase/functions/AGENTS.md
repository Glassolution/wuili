# Edge Functions — regras

- Escritas em Deno/TypeScript; nunca instalar pacotes Node.js para elas.
- Entitlement comes only from subscriptions through `subscriptionAccessPolicy.ts`; profiles.plano is an activation mirror, never fallback. Date enforcement is ValidaPay-only; lifetime/legacy providers use status. Hourly expiry audit stays ValidaPay-only with complete reads and backup/CAS, without financial actions.
- Monthly upgrades reserve an explicit quote, charge a ONE_TIME difference and replace the existing recurring item without prorata; intercept adjustment events before activation and never resend uncertain mutations, preserving billing dates and preventing duplicate contracts.
- Funções principais: `ml-publish`, `ml-connect`, `ml-callback` (salva token em `user_integrations`), `scrape-c7drop`, `catalog`, `chat` (Gemini).
- Suporte: a IA (`support-assistant`) responde tickets via gatilho no banco; avisos internos usam `support_messages.internal` e ficam ocultos do cliente pelas regras de acesso. Motivo: cobre todas as telas de envio de ticket.
- TikTok Events API: eventos de servidor passam por `_shared/tiktokEvents.ts` e ficam registrados em `tiktok_events` (event_id único). Motivo: evita duplicidade e permite reenviar falhas sem afetar o webhook de pagamento.
- Deploy: `supabase functions deploy <nome>`.
- Conferência de fotos (`_shared/catalogVisionReview.ts`, RPCs `cvr_*`) só registra evidência; recuperação de publicação só executa IDs aprovados de manifesto congelado, com snapshot/CAS. Motivo: evita publicação acidental.
- Support refund replies: within 7 days (or the verified admin exception) the fixed `support-assistant` reply links both `/ajuda/reembolso` and the cancel page; expired windows explain the deadline and link only cancellation, unless already cancelled or lifetime; a prior refund is explained as the reason, not an expired window. Motivo: clients need only the options available to their verified situation.
- Refund cooldown recovery uses the shared server-only `refundCooldown.ts` in ValidaPay confirmation and ML publication; require a non-trial active paid subscription created after the latest completed refund, with payment evidence, and compare-and-set the cooldown to avoid overwriting a concurrent refund. Identity refund blocks remain unchanged.
- ValidaPay ONE_TIME charges are not linked to checkout sessions and send no webhook; `_shared/lifetimeCharge.ts` matches paid charges by account email, exact amount and time window (used by `subscription-sync-self` and the `expire-pending-charges` cron) so paid lifetime buyers are never left without access. The time-only fallback for buyers who typed another email refuses charges whose email has a Velo account, charges with no email, and any charge another account's unpaid checkout of the same amount could claim within 3 days; read failures stop recovery instead of skipping these checks, and a unique index on lifetime charge IDs stops one payment from activating two accounts. This avoids handing a paying customer's plan to someone who abandoned checkout, at the cost of some cases going to support.
- Photo-review write failures (claim, evidence, verdict) are `ImageReviewInternalError`, logged in `ml_publish_errors` as `IMAGE_REVIEW_INTERNAL_ERROR`, and overdue-queue notices never abort a worker run; this keeps our bugs distinguishable from AI outages and stops one item from freezing the queue.
- Meta CAPI: Purchase do servidor via `_shared/metaCapi.ts` no bloco do TikTok do `validapay-webhook`, event_id `purchase_<subscription_id>` único em `meta_capi_events`; envio real só com `META_CAPI_ENABLED=true`. Motivo: deduplica com o pixel e só liga após o frontend usar o mesmo ID.
- `generate-store-banner` generates images directly via the Gemini API (`GEMINI_API_KEY`, `gemini-imagem.ts`) and uses the Lovable gateway only as a fallback when the key is missing or Gemini fails; keep this order in any change, because the owner chose to bill images to their own Gemini key.
